# OpenFnMusicAPI

飞牛音乐（FnMusic）Web 端 HTTP API 的非官方逆向资料与接口文档。

本仓库收录可公开阅读的全部资料：项目说明、脱敏后的 API 文档与只读验证脚本。文档与脚本自包含，不依赖仓库外的文件。

> 本项目不是飞牛音乐官方项目，不提供官方兼容性承诺。文档整理自公开 Web 前端、历史探测记录及授权实例上的只读验证；它不是完整 SDK 规范，也不证明已覆盖服务端全部路由或所有成功分支。

## 本次验证结论

验证对象为用户在会话中提供并明确授权的测试实例；地址、账号与密码**不写入仓库文件**。脚本只从环境变量读取，令牌仅保留在内存中，结束后主动登出。

### 环境与范围

| 项目 | 结果 |
|---|---|
| 登录页 | HTTP 200，`text/html`，SPA 入口正常 |
| 服务端版本 | 首次复核 `serverVersion 1.0.10`；同日复测 `1.1.19`（`mediasrvVersion` 均为 `0.8.43`） |
| 登录 | `POST /user/password-login` 成功；返回 `userToken` 与 `user`（`role=member`），无 `Set-Cookie` |
| 会话 | `GET /user/me` 成功；登出后原 token 被拒，符合 HTTP 401 / `99999` |
| 验证方式 | 仅只读请求、错误分支、成员权限拒绝、会话失效与一次 100 字节音频 Range |
| 证据规模 | 112 条用例：111 项断言通过，1 项为信息性观察，0 项失败、0 项跳过 |
| 覆盖 | 50 个「方法＋路径」；含列表、详情、搜索、封面、歌词、分页排序、错误码、管理接口拒绝等 |

验证明细由脚本在本地产出（默认 `readonly-results.json`），不纳入版本库。结果只记录 HTTP 状态、业务码、字段形状、响应头与脱敏断言，不记录密码、令牌、Cookie、真实 GUID、coverId、服务器目录或媒体正文；其中版本号与样本规模仍属实例指纹，对外分享前请自行评估。

### 与文档的符合情况

文档记录的主体协议与接口定义得到复现：

- `/music/api/v1` 基址、JSON `{code,msg,data}` 信封、`music-token` Cookie、SHA-256 密码摘要与 `deviceId` 登录形态；
- `sys/config`、`initialization/state`、`sys/info`、`user/me`、`user/logout`；
- 曲目 / 专辑 / 艺术家 / 流派 / 歌单 / 收藏 / 播放历史 / 共享库 / 任务列表，以及对应详情与关联列表；
- 搜索、suggest、歌词、封面读取、音频流 Range、未登录 401、成员访问管理接口返回 `100003`；
- 常规列表的 `page` / `size` / `sort` 行为，以及非法 sort 回退默认值的回显；
- 前端统一 fetch 客户端通过 HTTP header 发送 `authx`；本次所测只读请求不带该头或携带伪造值均未被拒绝，但不推断所有路由、写入请求或未来版本都不校验。
### 本次发现并已纳入文档的修正

1. **封面错误分支**：1.0.10 复核时，缺参数 / 空值 / 裸 GUID / 非前缀字符串为 HTTP 400 空体，而带已知前缀但不存在的 coverId 返回 **HTTP 404 `text/plain` 短正文**；1.1.19 复测所有非法形态又统一回到 HTTP 400 空体。客户端应按「非 JSON 错误」兼容处理，不能强制解析 JSON，也不应把 400 或 404 写成唯一分支。
2. **数据状态**：本次实例的收藏、播放历史与歌单样本不为空，因此不能沿用「最新账号为空」的叙述；但这些只是样本状态，不是接口上限或通用保证。
3. **搜索分页**：本次关键字样本只有 1 条命中，`page=1`/`page=2` 相同，只能标记为「样本不足、未证实分页生效」，不能作为忽略分页参数的证明。
4. **HLS**：未建立转码会话的合法格式 GUID 返回 HTTP 200 / `100005` JSON 错误；本次没有建立、保活或退出会话，因此仍不把会话生命周期标为最新实测成功。
5. **SPA 兜底**：不存在的 API 路径返回 HTTP 200 `text/html`，应按内容类型识别，不能因状态码 200 就当成 API 成功。

更完整的差异与未验证项清单见文档第 1、22 章。

### 1.1.19 复测（同日）

服务端升级后在同一实例复测：只读套件 112 条用例结果与首次一致（111 项通过、1 项信息性观察、0 失败），登录、会话、列表 / 详情 / 搜索 / 封面 / 歌词 / 播放历史 / 歌单与成员权限拒绝均正常。

- **新接口族**：`/folder-view/*` 共 5 条路由（`list`、`playable-tracks`、`add-to-playlist`、`delete`、`recover`），对应 `capabilities.folderView` 由 `false` 变为 `true`。目录整层一次返回、不分页；`delete` / `recover` 对成员返回 `100003`。
- **行为变化**：带真实前缀但不存在的 `coverId` 由 1.0.10 的 `404 text/plain` 回到 `400` 空体，见上文第 1 条。
- **接口计数**：前端注册表由 85 条唯一路径增至 90 条，方法＋路径组合由 85 增至 90；本文整理面由 90 增至 95（含 `sys/info`、`task/detail` 与 3 个直接资源 GET）。

复测明细由脚本在本地产出，同样不纳入版本库。新增接口族已写入文档第 15 章「文件夹视图」。

## 复现只读验证

需要 Node.js 24+，且只能用于自己拥有或已获书面授权的实例。在仓库根目录执行：

```bash
FNMUSIC_ORIGIN='https://<host>:<port>' \
FNMUSIC_USERNAME='<username>' \
FNMUSIC_PASSWORD='<password>' \
FNMUSIC_OUT='./readonly-results.json' \
node tools/verify-readonly.mjs
```

注意事项：

- 不要使用 `--trace-warnings`、代理日志或 shell `set -x` 记录含密码的环境变量；建议交互式输入或临时凭据。
- 结果文件不含凭据，但仍属于本地研究证据；对外分享前请自行复核。
- 脚本主动跳过了改密、用户管理、收藏/历史/歌单写入、封面上传、媒体库维护、索引重建、任务控制、转码会话、随机漫游、OAuth 与首次初始化等有副作用或需要专用环境的分支。详见结果文件的 `skippedByDesign`。
- 请勿以错误密码、空密码或重复登录去探测限流；这可能影响现用账号。
